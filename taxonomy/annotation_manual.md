# CVER可信知识库标注手册 v0.1.0

## 1. 标注原则

1. 先区分漏洞、错误配置、攻击模式和供应链事件，再分配根因标签。
2. 一级根因回答“哪一类安全不变量失效”，二级根因回答“具体由哪种机制失效”。
3. 攻击层、组件和影响不能替代根因。例如“容器逃逸”是影响，“runc”是组件。
4. 关键字段必须绑定证据片段。仅有参考链接而没有字段级证据，不满足Gold要求。
5. Gold事实不允许由大模型生成或决定。模型输出只能进入候选区。
6. 不知道必须标记为unknown或unverified，不得猜测。

## 2. 根因判定顺序

1. 阅读CNA或厂商公告。
2. 定位修复提交、补丁或源码差异。
3. 写出被破坏的安全不变量。
4. 写出触发输入、缺陷机制、利用原语和最终影响。
5. 使用反事实问题验证：只修复候选原因，核心攻击链是否被阻断？
6. 标注一级、二级根因，并映射到具体CWE。

## 3. 相邻类别边界

- 单组件路径解析错误属于RC-1.2；不同层对路径根解释不一致属于RC-5.2。
- 产品隔离实现被绕过属于RC-2；管理员主动配置hostPath或privileged属于RC-3.6。
- 单组件内部状态机错误属于RC-1.4；多个组件状态不同步属于RC-5.3。
- 直接缺少授权检查属于RC-3.2；低权限请求通过代理以宿主高权限执行属于RC-5.4。
- 镜像解析器内存漏洞属于RC-1.1；未验证镜像签名属于RC-4.1。

## 4. Gold准入

### CVE漏洞

必须同时具有：官方原始来源、补丁或源码证据、独立可靠来源、受影响版本断言、修复版本断言、Verified或Strong根因。

### 错误配置

必须同时具有：官方规范或安全文档、可重复实验、明确成功和阻断判据。

### 攻击模式与供应链事件

必须具有：真实事件、同行评审论文或权威分析，并将每个攻击步骤绑定证据。

## 5. 可利用性标注

按顺序标注：环境条件、入口可达性、利用链完整性、实验验证等级。条件采用TRUE/FALSE/UNKNOWN三值逻辑，UNKNOWN不得按FALSE处理。
